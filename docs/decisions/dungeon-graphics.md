# 던전 그래픽 생성 방식

## Decisions

- 던전 뷰와 추격자, 미니맵의 도트 그래픽은 코드로 그립니다. 이미지 에셋 파일을 저장소에 두지 않습니다.

## Boundaries

- 던전 뷰, 추격자, 미니맵에만 적용됩니다. 스도쿠 보드와 일반 UI는 기존 컴포넌트를 그대로 씁니다.
- 렌더링 기술까지 정하지는 않습니다. canvas든 SVG든 CSS든 이 결정과 무관합니다.

## Why

저장소에 픽셀아트 에셋이 하나도 없습니다. `public/`에는 Next.js 기본 SVG 다섯 개뿐이고, 스타일이 일관된 스프라이트 세트를 확보할 경로도 없었습니다. 에셋을 도입하면 그리는 사람, 라이선스, 스타일 일관성 문제가 한꺼번에 따라옵니다.

절차적으로 그린 복도가 실제로 던전으로 읽히는지는 렌더로 확인했고, 저해상도에서 충분히 읽혔습니다. 즉 이 제약이 결과물의 질을 크게 깎지 않습니다.

## Reconsider when

- 스타일이 일관된 픽셀아트 에셋 세트를 라이선스 문제 없이 확보했을 때
- 절차적 렌더링으로 만들 수 없는 연출이 제품에 필요해졌을 때

## Still-rejected alternatives

- 스프라이트 이미지 에셋 도입 — 확보 경로가 없어 작업 자체가 막힘; 에셋 세트를 갖추면 재검토합니다.

## Evidence worth preserving

- 중첩 사다리꼴로 원근을 만들고 깊이별 명암과 석조 줄눈을 얹으면, 160×120 해상도에서도 1인칭 던전 복도로 읽힙니다. 세 가지 변형(빈 복도 / 복도+추격자 / 복도+추격자+하단 UI)을 비교해 확인했습니다.
- 하단 UI 변형은 던전이 보이는 면적을 약 4분의 1 잡아먹으면서, 그 자리의 손과 무기가 게임에서 아무 역할도 하지 않아 탈락했습니다.
